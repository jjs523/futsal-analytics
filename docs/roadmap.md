# 로드맵 (2026년 10~11월, 1차)

## 방향: 서버 없이 휴대폰에서 모두 처리

서버 비용을 없애기 위해 **촬영부터 분석, 결과 확인까지 폰 2대 안에서 끝냅니다.** 구조는 [시스템 구조](architecture.md)에 있습니다.

| | 트랙 A: 분석 품질 (PC) | 트랙 B: 앱 (폰) |
|---|---|---|
| 목적 | 실제 영상으로 **정답 결과**를 만들고 모델을 고름 | 같은 처리를 **폰 안에서** 돌림 |
| 도구 | `src/futsal/` Python 코드, 개발용 PC 도구(`server/`) | Flutter, Ultralytics YOLO 플러그인 |
| 산출물 | 폰용 검출 모델(CoreML / TFLite), 정확도 기준값 | 촬영 → 검출 → 병합·추적 → 결과 화면 앱 |

트랙 A가 "이렇게 하면 이 정도 정확도"를 PC에서 먼저 확인하고, 트랙 B가 같은 결과를 폰에서 재현합니다. 두 트랙은 같은 파일 형식(`det.json`, `calib.json`, `tracks.json`)을 써서 서로 결과를 비교할 수 있습니다.

## 지금 된 것 (이 저장소)
- FIFA 규격 코트, 기준점 29개 탭 보정, 두 카메라 병합, 경기장 위 추적, 칼만 스무딩 지표 (Python 기준 구현)
- 배치·화각 시뮬레이터와 결과 문서
- 개발용 PC 도구(업로드, 보정, 분석, 결과)와 2D 지도 웹 뷰어
- 합성 영상으로 전체 흐름 테스트
- 공 검출 도구: 라벨링 프레임 뽑기 → 조각 학습 데이터 → 학습 → 조각 검출 + 궤적 정리 ([공 검출](ball-detection.md))

## 이번 주에 할 일 (가장 중요)

1. **테스트 촬영** ([촬영 가이드](capture-guide.md) 그대로)
   - 대각선 코너 2곳, 삼각대 2m 이상, 1x, 상대 폰이 화면 가로 약 57% 지점에 오게
   - 10~15분, 시작과 끝에 손뼉
   - 콘 5개 정도를 놓고 줄자로 좌표 기록, 사람이 그 위에 5초씩 서 있기
   - 구장 라인 크기 실측, 삼각대 위치·높이 기록
2. **팀원 폰 전부에서 검출 속도 측정**: [측정 방법](phone-benchmark.md) 그대로. **최저 사양 기종이 몇 분 걸리는지가 설계를 정합니다.**
3. **개발 환경**: `pip install -e ".[server,sim,dev]"` → `pytest`, Flutter SDK 설치
4. **역할 분담**: 아래 [파트 분배](#파트-분배-5명-비전-3--백엔드-2) 참고

## 파트 분배 (5명: 비전 3 + 백엔드 2)

서버 없이 폰에서 처리하므로, **백엔드는 "앱 안의 처리 엔진과 데이터 흐름"**을 맡습니다. 화면(UI)은 프론트 담당이 따로 맡습니다.

| 파트 | 맡을 일 | 코드 위치 | 첫 2주 목표 |
|---|---|---|---|
| **비전 1: 검출** | YOLO 모델 선택(n/s), 실제 영상 파인튜닝, 폰용 변환(CoreML/TFLite), 팀원 폰 속도 측정, 라벨링 기준 정하기, **공 검출 학습** | `pipeline/detect.py`, `ball/`, `docs/phone-benchmark.md`, [공 검출](ball-detection.md) | 팀원 폰 속도표, 실제 영상에서 먼 선수 놓치는 비율 |
| **비전 2: 추적·ID** | 생김새 특징, 조각 끊기·다시 묶기, 키 단서, 팀 자동 분류, 경량 Re-ID 검토, IDF1 평가 | `pipeline/pitch_tracker.py`, `sim/evaluate.py`, [조사 문서](tracking-survey.md) | 실제 영상 3분 라벨링 → 실제 IDF1 측정 |
| **비전 3: 좌표·동기화·지표** | 기준점 보정, 두 영상 시간 맞추기, 두 카메라 병합, 이동거리·속도, **콘으로 위치 정확도 측정**, 배치 시뮬레이션 | `homography.py`, `sync.py`, `fusion.py`, `metrics.py`, `sim/` | 이번 촬영 영상 시간 맞추기 + 콘 위치 오차표 |
| **백엔드 1: 폰 처리 엔진** | 녹화 파일 프레임 읽기 → 모델 실행 → `det.json` 저장, 백그라운드·충전 중 처리, 발열·속도 최적화, 분석 코어(보정·병합·추적·지표) Dart 이식 | (새로) `app/` 엔진 부분 | 폰에서 `det.json` 생성 → PC 결과와 같은지 비교 |
| **백엔드 2: 데이터·연결** | QR 짝짓기, 두 폰 시계 차 측정, 폰끼리 결과 전송, 경기·구장·보정값 로컬 저장, 결과 내보내기(이미지·파일), (선택) 무료 클라우드 공유, 개발용 PC 도구·테스트 유지 | (새로) `app/` 데이터 부분, `server/`, `tests/` | 두 폰 짝짓기 → 시계 차 측정 → 테스트 파일 전송 |

**같이 맞춰야 하는 경계**
- 비전 1 ↔ 백엔드 1: 모델 파일 형식, 입력 크기, 폰별 속도
- 비전 2·3 ↔ 백엔드 1: `det.json`·`calib.json`·`tracks.json` 형식. 바꿀 때는 셋이 함께 정하고, Python 테스트를 정답 비교용으로 사용
- 백엔드 2 ↔ 비전 3: 시계 맞추기(앱의 시계 차 측정 + 소리 보조)
- 프론트 ↔ 백엔드 1·2: 촬영 안내, 보정 탭 화면, 결과 화면에 필요한 데이터

**공통 업무:** 촬영과 라벨링은 다 같이 합니다. 일정·문서·발표는 매주 돌아가며 한 명이 정리합니다.

## 결정해야 할 것
- 최저 지원 기종 (검출 속도 측정 결과로 정함)
- 검출 모델 크기: YOLO11n(빠름) / YOLO11s(정확), 타일링 사용 여부
- 결과 공유 방식: 이미지만 / 파일 / 무료 클라우드 링크
- 평가 지표: 위치 오차(콘 기준), 선수별 ID 유지율, 기종별 처리 시간
