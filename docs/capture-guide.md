# 촬영 가이드

일반 휴대폰 2대 + 삼각대 2개 기준입니다. 근거는 [시뮬레이션 결과](simulation.md)에 있습니다.

## 설치

![권장 배치](img/court_spec.png)

| 항목 | 권장 | 이유 |
|---|---|---|
| 위치 | **대각선 두 코너**, 라인 밖 약 1~1.5m (펜스 안쪽 런오프) | 1x 렌즈로 두 대가 가장 많이 보는 위치. 코트 둘레 모든 위치를 전수 탐색한 결과 1등 |
| 높이 | **2m 이상** (사람 키보다 높게) | 1.5m면 가까운 선수 머리가 잘리고 겹침이 늘어남 |
| 렌즈 | **1x** (0.5x가 있으면 더 좋음, 선택) | 1x는 모든 폰에 있음. 0.5x는 두 대가 코트 100%를 함께 봄 |
| 방향 | 서로 마주보게 놓고 **왼쪽으로 조금 돌림** → 상대 폰이 **화면 가운데에서 약간 오른쪽**에 보이게 | 두 대가 함께 보는 영역이 74% → 80%로 늘어남 |
| 화면 | 가로, 코트 네 모서리와 하프라인이 최대한 많이 보이게 | 보정 기준점이 많을수록 정확 |

### 구장 크기별 "상대 폰 위치" (화면 가로폭 기준, 왼쪽 0% ~ 오른쪽 100%)

| 구장 | 화각 좁은 폰 (아이폰 기본형 등) | 화각 넓은 폰 (갤럭시 S·Flip 등) |
|---|---|---|
| 30×15, 38×18, 40×20 | 약 57% (5° 회전) | 약 56% (5° 회전) |
| 42×25 (폭이 넓은 구장) | **약 53% (2° 회전)** | 약 56% (5° 회전) |

모르면 **정중앙(마주보기)**에 두세요. 어느 구장에서도 안 보이는 구역이 생기지 않습니다. 너무 많이 돌리는 쪽만 조심하면 됩니다. 정확한 값은 `python -m futsal.sim twist --court 가로x세로`로 계산합니다(앱에서는 자동 계산해서 표시할 예정).

## 휴대폰 설정

| 설정 | 값 |
|---|---|
| 해상도 / 프레임 | **1080p(FHD)**, 두 폰 모두 지원하면 **60fps**, 아니면 30fps ([해상도](#해상도-4k-vs-1080p), [프레임 수](#프레임-수-60fps-vs-30fps)). 자동 프레임·슬로모션은 끄기 |
| 손떨림 보정 | 일반 보정은 켜져 있어도 됨. **슈퍼 스테디·액션 모드는 끄기** (화면을 크게 잘라냄) |
| 초점·노출 | 코트를 길게 눌러 **고정 (AE/AF 잠금)** |
| 비행기 모드 | 켜기 (전화·알림으로 녹화가 끊기는 것 방지) |
| 배터리 / 저장공간 | 1080p 50분 ≈ 3~6GB. 보조배터리 연결 권장. **분석도 폰에서 하므로 경기 후 충전기 필요** |

## 시작 순서 체크리스트

1. 두 폰을 설치하고 위 방향대로 맞춘다 (앱 화면에 상대 폰 위치 표시가 나옴)
2. 앱에서 **QR로 두 폰 연결** (같은 와이파이나 한 폰의 핫스팟). 이때 두 폰의 시계 차이를 자동으로 잽니다
3. 두 폰 모두 녹화 시작
4. **코트 중앙에서 손뼉 한 번** (시간 맞추기 예비 수단. 시계 차이를 못 쟀을 때 소리로 맞춤)
5. 경기 (경기 중에는 녹화만 합니다. 분석을 같이 돌리면 발열로 녹화가 끊길 수 있음)
6. 끝나면 손뼉 한 번 더 → 녹화 종료
7. 각 폰에서 보이는 기준점 탭 (구장·삼각대 위치별로 한 번, 다음부터는 저장된 값 사용)
8. **두 폰 모두 충전기에 꽂고 분석 시작** → 폰 2의 검출 결과가 폰 1로 전송 → 폰 1에서 결과 확인·공유

분석 시간은 폰에 따라 5분(최신 플래그십)부터 1~2시간(보급형)까지 걸립니다. 자세한 건 [시스템 구조](architecture.md#선수-검출-처리-시간-예상) 참고.

## 두 영상 시간 맞추기 (앱이 생기기 전, 기본 카메라로 찍을 때)

두 영상 모두에 **같은 순간**이 남도록 소리와 화면 두 가지로 표시합니다.

| 언제 | 할 일 |
|---|---|
| 두 폰 녹화를 켠 직후 | 코트 가운데에서 **두 손을 머리 위로 올려 크게 손뼉 3번**. 다른 폰에 **밀리초까지 나오는 시계**(예: time.is)를 띄워 두 카메라 렌즈 앞에 2~3초씩 보여 주기 |
| 경기 중 | 멈추거나 일시정지하지 않기. **두 폰 모두 같은 프레임 수** (둘 다 60fps 또는 둘 다 30fps) |
| 녹화를 끄기 직전 | 손뼉 3번 + 시계 화면 한 번 더 (두 폰 시계의 속도 차이 보정용, 50분이면 약 0.1초 벌어질 수 있음) |
| 촬영 후 | **원본 파일 그대로** 옮기기: USB 케이블, AirDrop, 구글 드라이브 원본 업로드. **카톡 전송 금지** (다시 압축되고 촬영 시각 정보가 지워짐). 영상 자르기·편집 금지 |

PC에서 시간 차이 계산:
```bash
python -m futsal.sync 20261008_170919.mp4 20261008_171122.mp4
# (출력 예시)
# 대략적인 시작 차이 +123 s 주변 ±5 s에서 찾습니다
# 구간 53개 중 50개가 일치, 표준오차 0.015 s
# 시계 속도 차이:    +0 ppm  (측정 오차 안이라 0으로 둠)
#    분석에 넣을 값: {"offset": 124.29, "drift": 0.000e+00}
```
경기 전체를 1분씩 나눠 각각 시간 차를 재고, 서로 맞는 구간들로 최종 값을 냅니다. **손뼉이 없어도 경기 소리(공 차는 소리, 말소리)로 맞출 수 있습니다.** 한 구간만 보면 비슷한 소리를 잘못 짝짓거나, 두 폰이 40m 넘게 떨어져 있어 소리가 도착하는 시각이 최대 ±0.13초 달라지기 때문에 여러 구간을 모아야 정확해집니다 ([2026-10-08 촬영 기록](capture-2026-10-08.md)).

일치하는 구간이 적거나 표준오차가 0.05초보다 크면, `python -m futsal.syncview cam1.mp4 cam2.mp4 --offset 값`으로 같은 순간 장면을 나란히 놓고 눈으로 확인합니다. 손뼉이 있는 영상은 `--method ends`(시작·끝 2분만 비교)도 쓸 수 있습니다. 폰마다 녹화 프레임 간격이 일정하지 않을 수 있어서, 분석은 프레임 번호가 아니라 **각 프레임의 실제 시각**을 씁니다.

## 해상도: 4K vs 1080p

| | 1080p | 4K |
|---|---|---|
| 파일 크기 (30fps, HEVC 기준) | 분당 약 60MB | 분당 약 170MB (30분 ≈ 5GB) |
| 선수 검출 (화면 전체를 640px로 줄여 1번) | 기준 | **거의 같음** (영상 읽기·줄이기만 무거워짐) |
| 공 조각 검출 (640px 조각) | 한 장에 8조각 | 한 장에 32조각 (**약 4배 느림**) |
| 먼 공 크기 (30m) | 약 9px | 약 18px |

- **1080p(FHD)로 정했습니다.** 파일이 작고(30분 ≈ 2GB), 폰 처리 비용과 앱 조건이 테스트 영상과 같아서 PC 결과를 그대로 앱 기준으로 쓸 수 있습니다.
- 대신 먼 공은 6~9px로 작습니다. 공은 원본 해상도 조각 검출로 보완하고, 반대편 코너 쪽 공 라벨을 충분히 모읍니다.
- 먼 쪽 공·선수를 놓치는 비율이 너무 높게 나오면 그때 4K를 짧게 찍어 비교합니다.

## 프레임 수: 60fps vs 30fps

**두 폰 모두 1080p 60fps를 지원하면 60fps로 찍습니다.** 공 추적에 확실히 유리하고, ID 추적·시간 맞추기에도 조금 유리합니다.

| | 30fps | 60fps |
|---|---|---|
| 공 번짐 (초속 20m 슛, 최대 노출 기준) | 최대 약 67cm | 최대 약 33cm |
| 프레임 사이 공 이동 (초속 20~30m) | 0.7~1m | 0.3~0.5m (궤적 잇기 쉬움) |
| 프레임 사이 선수 이동 (초속 7m) | 약 23cm | 약 12cm |
| 두 영상 시간 맞춤 오차 (반 프레임) | 약 17ms | 약 8ms |
| 파일 크기 (1080p) | 30분 ≈ 2GB | 30분 ≈ 3~4GB |
| 지원 기종 | 모든 폰 | 오래된 폰·저가 보급형(갤럭시 A 일부 등)은 미지원 |

- **처리 비용은 늘리지 않아도 됩니다.** 선수 검출은 프레임 수가 아니라 시간 기준(예: 초당 10번)으로 보고, 공은 필요하면 2장마다 1장만 봐도 번짐이 적은 이점은 남습니다.
- **어두운 구장**에서는 60fps 화면이 어둡고 거칠어질 수 있습니다. 시험 녹화로 확인하고, 너무 어두우면 30fps로 찍습니다.
- 60fps로 찍으면 PC에서 한 장씩 건너뛰어 30fps 결과와 비교할 수 있습니다 (반대는 불가).
- 앱은 30fps에서도 동작하도록 만들고, 두 폰이 지원하면 60fps를 씁니다.
- 확인 방법: 아이폰은 설정 → 카메라 → 비디오 녹화, 갤럭시는 카메라 → 동영상 → 위쪽 해상도 아이콘에서 `FHD 60`.

## 테스트 촬영 체크리스트 (위치 정확도 · ID 추적 · 공 데이터를 한 번에)

### 가기 전 준비물
- 삼각대 2개 (2m 이상), 보조배터리, 저장공간 (1080p 30분 ≈ 2GB, 여유 있게 5GB)
- **줄자**, **콘 5~9개** (없으면 물병·가방)
- **두 색 조끼**: 팀끼리 확실히 다른 색. 가능하면 하의 색도 팀끼리 겹치지 않게 (생김새로 ID 구분할 때 중요)
- **공은 하나만** 코트에 (예비 공은 가방에)
- 밀리초까지 나오는 시계 화면을 띄울 폰 하나 (time.is)

### 설치
- 위 [설치](#설치)와 [휴대폰 설정](#휴대폰-설정) 그대로 (대각선 코너, 2m 이상, 1x, 상대 폰이 화면 가로 약 57%)
- **10초 시험 녹화** → 재생해서 코트 네 모서리와 하프라인이 보이는지 확인

### 촬영 순서 (녹화는 처음부터 끝까지 끊지 않기)

| 순서 | 할 일 | 쓰는 곳 |
|---|---|---|
| ① 시작 | 코트 가운데에서 **손뼉 3번** + 시계 화면을 두 렌즈 앞에 2~3초씩 | 시간 맞추기 |
| ② 빈 코트 30초 | 모두 코트 밖으로 | 기준점 보정, 배경 |
| ③ 콘 위치 | 콘 자리에 한 사람씩 **5초씩** 서 있기 (센터, 페널티 마크, 코너에서 5m 지점 등) | 위치 오차 측정 |
| ④ ID 장면 (각 2~3번) | 같은 팀 두 명 교차 / 다른 팀 두 명 교차 / 나란히 뛰다 갈라지기 / 3~4명 뭉쳤다 흩어지기 / 코트 밖으로 나갔다 다시 들어오기 / 카메라 바로 앞 지나가기 | 추적·ID: ID가 바뀌는 대표 상황 |
| ⑤ 공 장면 | 드리블, 짧은 패스, 긴 패스, 슛, 공 높이 띄우기, 골키퍼가 잡기. **가까운 쪽과 먼 쪽 모두** | [공 검출](ball-detection.md) 라벨링 |
| ⑥ 자유 경기 | **10~15분** 평소처럼 | 실제 상황 전체 |
| ⑦ 끝 | 손뼉 3번 + 시계 화면 한 번 더 | 시계 속도 차이 보정 |

④는 일부러 만드는 장면이라 정답 라벨링이 쉽습니다. 실제 경기보다 먼저 이걸로 추적이 어디서 틀리는지 봅니다.

### 현장에서 적어 둘 것 (사진도 됨)
- 구장 실제 크기 (줄자): 가로, 세로, 페널티 에어리어
- 콘 위치 좌표: 기준 모서리에서 가로·세로 몇 m
- 삼각대 위치·높이, 두 폰 기종
- **누가 어떤 조끼·하의를 입었는지** (정답 ID 만들 때 필요)
- ③~⑥ 각 장면을 시작한 대략의 시각

### 촬영 후
- **원본 그대로** 옮기기 (USB, AirDrop, 구글 드라이브 원본 업로드). 카톡 금지, 자르기·편집 금지
- **파일 이름은 바꾸지 않기** (`20261008_170919.mp4`처럼 녹화 시작 시각이 들어 있어 시간 맞추기에 씀). 각 파일이 어느 코너 폰인지 메모

### 영상 점검 (PC)
```bash
python -m futsal.check 20261008_170919.mp4 20261008_171122.mp4 --out check_report
```
해상도·프레임 수·길이, 프레임 간격(끊김·가변 프레임), 밝기·선명도, 9칸 미리보기(`*_sheet.jpg`), 소리로 맞춘 시간 차이를 `check_report/report.txt`에 정리합니다. 시간 맞추기에는 ffmpeg가 필요합니다 (윈도우: `winget install ffmpeg`).

**두 폰을 몇 분 차이로 켰을 때:** 넓은 범위를 찾으면 비슷한 소리를 잘못 짝지을 수 있어서, 파일 이름의 녹화 시각(`20261008_170919` = 17:09:19 시작)으로 대략적인 차이를 먼저 잡고 그 주변 ±5초만 찾습니다. 메타데이터의 `creation_time`은 삼성 폰에서 녹화 **종료** 시각이라 쓰지 않습니다. 파일 이름을 바꿨다면 `python -m futsal.sync cam1.mp4 cam2.mp4 --hint 123`처럼 직접 넣습니다.
## 측정 정확도 평가용 (테스트 촬영 때만)

- 코트 안 정해진 위치(예: 페널티 마크, 센터, 코너에서 5m 지점)에 **콘이나 사람**을 세우고 줄자로 실제 좌표를 기록
- 그 위치에 서서 5초씩 머무르기 → 추정 좌표와 비교
- 실제 구장의 라인 크기를 줄자로 재서 기록 (규격과 다를 수 있음)
